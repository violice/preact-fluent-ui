# Sidebar и AppShell для приложений

Статус: предложение первого этапа одобрено пользователем 2026-10-05;
этот документ подготовлен для проверки перед планированием реализации.

## Цель

Заменить повторяющуюся разметку навигации и оболочки в Route VPN компонентами preact-fluent-ui. Сохранить маршруты, query-параметры,
локальное состояние, операции Windows и поведение диалогов приложений.
Sidebar должен подходить и для документации, и для небольших desktop-приложений.

Работа охватывает библиотеку, её gallery и одну полную проверочную миграцию в
/home/violice/dev/route-vpn. Hosts Editor, Port Proxy и XBOX DNS остаются
источниками требований и не изменяются. Таблицы, Toolbar и Pagination
относятся к следующим этапам. Существующие формы, диалоги и состояния
Route VPN входят в текущую миграцию.

## Выбор подхода

Развиваем существующий составной Sidebar и добавляем отдельный составной
AppShell. Это сохраняет произвольные блоки и независимость от роутера.
Единый компонент с массивом пунктов потребовал бы дополнительных исключений
для действий и footer. Перенос только CSS сократил бы дублирование стилей,
но оставил бы доступность и структуру на каждом приложении.

## Sidebar

Существующие экспорты и их поведение по умолчанию сохраняются.

- Sidebar получает appearance="default" | "app", по умолчанию default,
  layout="expanded" | "rail" | "horizontal", по умолчанию expanded,
  и scrollable boolean, по умолчанию false. Layout управляется приложением;
  Signals поддерживаются для layout и scrollable. DOM остаётся aside.
- SidebarNav при scrollable занимает доступное место и прокручивается.
  Header и Footer не сжимаются. Нужна заданная высота внешнего контейнера.
- SidebarBrand добавляет logo как ComponentChildren, обязательный title
  как string и необязательный description как string. Корень div, стандартные
  HTML props и ref, slots root/logo/content/title/description. Логотип
  декоративный; содержимое logo не должно включать интерактивные элементы.
- SidebarItem остаётся ссылкой с обязательным href. Добавляется description
  как string и slot description; существующие children остаются подписью.
  Добавляется необязательный label как string для краткого доступного имени
  и подсказки в rail, когда children содержит сложную разметку. Если label
  отсутствует, доступное имя берётся из children.
- SidebarAction является отдельным button с icon, children, description,
  label и slots root/icon/content/description. Стандартные button props,
  ref, type="button" по умолчанию, нативный disabled. Не получает active
  или aria-current. Оформление соответствует SidebarItem.

В rail текст пунктов визуально скрывается с сохранением доступного имени,
description скрывается и исключается из имени; иконки центрируются.
Пункты без иконки сохраняют видимую подпись, чтобы не стать пустыми.
Brand показывает логотип; при отсутствии логотипа сохраняет title.
Подписи групп скрываются визуально, но продолжают именовать группы.
Для строковых children либо label библиотека показывает краткую подсказку
при hover и focus-visible только в rail. Подсказка не является интерактивной,
не влияет на размеры панели и не создаёт повторного доступного имени.
Это локальная часть Sidebar, не новый публичный Tooltip.

В horizontal навигация становится строкой, подписи пунктов видимы, индикатор
активности располагается снизу. Группы размещаются в строку; длинное меню
может прокручиваться горизонтально. Brand и footer произвольного содержания
приложение может скрывать через стандартный hidden. Действия остаются доступны.

appearance="app" задаёт минимальную высоту пункта 44px и оформление из
проверенных приложений. Default сохраняет gallery без визуальной миграции.
Цвета настраиваются локальными переменными --sidebar-background,
--sidebar-hover-background, --sidebar-active-background,
--sidebar-active-color; значения по умолчанию используют текущие токены темы.

## AppShell

Публичные компоненты AppShell, AppShellWorkspace, AppShellHeader,
AppShellContent и AppShellFooter принимают стандартные HTML props и ref.
AppShell является div, Workspace является main, остальные части div.
Приложение размещает Sidebar и Workspace непосредственными детьми AppShell.
В Workspace располагает Header, Content и Footer по необходимости. Один
main в документе; оболочка не создаёт скрытых main или дополнительных landmark.

AppShell получает navigationLayout="expanded" | "rail" | "horizontal",
по умолчанию expanded, с поддержкой Signals. Это единственное состояние
геометрии: то же значение приложение передаёт в Sidebar.layout.
Компонент не вызывает matchMedia, не читает роутер и не перемещает фокус.
AppShellWorkspace сохраняет поддержку ref и tabIndex для существующих
потребителей. Новое программное перемещение фокуса не добавляется.

Expanded использует две колонки с шириной навигации 248px по умолчанию.
Rail использует 64px. Horizontal размещает навигацию над рабочей областью.
Переменные --app-shell-navigation-width, --app-shell-rail-width,
--app-shell-content-max-width и --app-shell-content-padding задают размеры.
Content имеет min-width:0, border-box, max-width:1240px и центрирование.
Workspace имеет flex-column и flex:1 у Content, чтобы footer оставался снизу.
Desktop workspace имеет внешний отступ 8px, рамку и радиус 12px;
horizontal убирает внешние отступы и радиус. Цвета используют текущую тему
с возможностью переопределения классов. Высота shell min-height:100dvh.
Sidebar в desktop sticky, top:0 и height:100dvh; в horizontal высота auto.

CSS не предполагает наличие reset.css. Все новые контейнеры и контролы
работают с Minimal и Full. class имеет приоритет над className как fallback,
пользовательские классы дополняют встроенные. hidden сохраняет нативное
поведение. Логические отступы и индикаторы поддерживают RTL.

## Проверочные миграции

Route VPN сейчас использует пакет 0.1.0. Проверка производится через один
собранный npm archive текущей библиотеки, установленный локально в Route VPN. Не публиковать пакет и не оставлять абсолютные file-зависимости
в tracked manifest/lockfile. Перед проверкой сохранять исходные зависимости;
локальная установка нужна только для валидации до релиза новой версии.
Исходный код миграции остаётся в приложениях и требует нового релиза пакета.
Эту зависимость явно отмечать в результате, не заявлять готовность приложений
к чистой установке с опубликованной 0.1.0.

Route VPN сохраняет breakpoint 992px для rail и 640px для horizontal,
query-параметры, routesFocusRef и действие открытия параметров Windows.
Для переключения layout добавить небольшой локальный hook matchMedia
с очисткой подписок; бизнес-модели не меняются. При SSR исходное значение
expanded, чтение окна после mount.

Полная адаптация Route VPN означает применение актуальных компонентов
к существующим сценариям, без добавления искусственных функций:

- RoutePrefixInput использует Input и Field. Сохраняются inputRef,
  первоначальный фокус, валидация IPv4/CIDR и ввод с клавиатуры. Связать
  подсказки и ошибку с контролом через Field, исключить повторные сообщения.
- SplitTunnelingSwitch использует Switch с прежними checked, disabled,
  openerRef и обработчиком. Удалить собственные track/thumb стили.
- Настройка подтверждения переключения использует Checkbox, если текущая
  разметка содержит checkbox. Сохраняются настройка и её семантика.
- VpnPicker использует актуальный Select classes.wrapper; существующая
  подпись и иконка сохраняются. Field можно использовать для общей связи
  подписи с контролом без изменения выбора профиля.
- RemoveRouteDialog использует ConfirmDialog с первоначальным фокусом
  на Cancel, прежним fallbackFocusRef и danger. Подтверждение переключения
  сохраняет текущую последовательность и выбранный первоначальный фокус;
  перевод на ConfirmDialog допустим только если его API это сохраняет.
- Сложная форма добавления и подтверждение широкого префикса сохраняют
  Modal и составные DialogHeader/Body/Footer.
- WorkspaceState использует EmptyState для ошибки и отсутствия профилей;
  loading сохраняет role=status. Button, Card, InfoBar, StatusBadge,
  PageHeader и Icon остаются основой других экранов; удалить только CSS,
  который повторяет их оформление. Сохранить интервалы и порядок notices.

Проверить все четыре страницы Route VPN: маршруты, диагностика, профиль,
About. Не вводить Textarea или другие контролы без соответствующего поля.
Не добавлять отсутствующие Spinner/Table как условие этой миграции.
Сохранить порядок добавления маршрута: проверка дубликата, успешное
добавление, закрытие модалки, обновление списка. Ошибка дубликата остаётся
видимой, а не подавляется. На навигации фокус остаётся на ссылке; новый
программный фокус на заголовки или текст не добавляется.

Из shared/ui реэкспортировать необходимые части библиотеки. Локальные
AppShell переименовывать или импортировать библиотечный AppShell под alias,
чтобы сохранить архитектуру приложений. Удалять только заменённые стили.
В рамках перехода 0.1.0 на текущий пакет заменить wrapperClassName у Select
на classes.wrapper и проверить остальные использованные изменённые props.

## Документация и проверки

Gallery сохраняет своё текущее оформление и навигацию. Добавить страницы
новых публичных компонентов и примеры expanded, rail, horizontal, действия
и отдельного скролла. Действия примеров локальны; сообщения InfoBar идут
сразу после live Example, с видимым отступом, до кода. Компоненты в sidebar
gallery остаются отсортированными по английскому названию.

Проверить unit-тестами нативные ссылки, кнопки и disabled, refs, Signals,
aria-current, description, доступные названия rail, class slots и hidden.
Проверить переключение ширины в приложениях, сохранение query и Windows
callback, диалоги и возврат фокуса без изменения существующей логики.
Проверить сборку, декларации и установку npm archive в Route VPN.
Обновить README/API и changelog без публикации и изменения версии на этом этапе.

Браузерная проверка включает 320, 640, 768 и 1280px, оба оформления темы,
Minimal/Full, длинные подписи, 200% zoom, RTL, keyboard и длинное меню.
При маленькой высоте header/footer доступны, nav прокручивается, tooltip
не обрезается контейнером scroll. Проверить active/focus в forced-colors
и отсутствие ненужной анимации при reduced-motion.

## Критерий завершения

В Route VPN навигация и общий каркас используют библиотеку;
локальные CSS отвечают за особенности страниц. Проверки библиотеки и Route VPN проходят на одном архиве. Gallery документирует новый API,
старые примеры Sidebar продолжают работать. Публикация пакета, push и
релиз приложений остаются отдельными действиями.
