# Галерея документации и составной Sidebar

Статус: согласовано пользователем 2026-10-04, реализовано и проверено 2026-10-05.

## Цель и границы

Превратить существующую галерею в документацию библиотеки с отдельными
страницами компонентов, первыми шагами и настройкой темы. Добавить preact-iso
для маршрутов и @preact/signals для состояния галереи и живых примеров.
Работать только в preact-fluent-ui. Миграция приложений не входит в задачу.

Визуальная основа Sidebar — AppNavigation из port-proxy, hosts-editor и
xbox-dns: бренд, ссылки, акцентная полоса активного пункта, нижний блок.
Публичный API должен позволять собирать разные структуры из компонентов,
а не требовать фиксированного массива пунктов или конкретного роутера.

## Варианты

1. Составные публичные компоненты библиотеки и отдельная оболочка галереи.
   Рекомендуется: даёт переиспользование и свободу композиции.
2. Один Sidebar с конфигурацией пунктов, бренда и footer. Проще первоначально,
   но нестандартные блоки и действия требуют расширять интерфейс.
3. Sidebar только внутри галереи. Меньше публичного API, но оставляет
   повторяющиеся реализации в приложениях и не выполняет цель переиспользования.

## Предлагаемый публичный API

- Sidebar: aside, children, стандартные HTML props и ref. Вертикальный
  контейнер; высотой, sticky-позицией и шириной управляет внешняя оболочка.
- SidebarHeader: div с произвольным children для бренда или другого содержимого.
- SidebarNav: nav с children и обязательным aria-label либо aria-labelledby.
- SidebarGroup: div с необязательным label и children, объединяет пункты.
  При наличии label связывает подпись с группой через aria-labelledby.
- SidebarItem: ссылка a с обязательным href, children, необязательными icon
  как ComponentChildren и active как JSX.Signalish<boolean>. Активный пункт
  получает aria-current="page". Сохраняет стандартные anchor props и ref.
- SidebarFooter: div с children, располагается внизу через margin-top: auto.

SidebarItem не становится кнопкой через переключающий prop. Для действий
можно разместить существующий Button в любом блоке. Родитель приложения
определяет активность и URL; библиотека не импортирует preact-iso или signals.

У всех компонентов class имеет приоритет над className как fallback,
пользовательские классы добавляются к встроенным, SignalLike поддерживается.
У одноэлементных компонентов нет classes. У SidebarGroup допустимы slots
root/label/content, у SidebarItem root/icon/content. Оба являются multipart.
Не создавать скрытых обёрток вокруг остальных компонентов.

Навигация остаётся обычной навигацией со ссылками, без menu-ролей и управления
стрелками. Клавиатура работает через Tab и Enter. Индикатор активности,
focus-visible, длинные подписи, RTL и forced-colors поддерживаются стилями.

## Структура галереи

Постоянная оболочка: Sidebar, основной контент и компактный блок глобальных
настроек внешнего вида. Навигация группируется на начало работы, компоненты
и руководства. На узком экране оболочка предоставляет кнопку показа
навигации с aria-expanded/aria-controls; меню закрывается после выбора ссылки.
Сам библиотечный Sidebar не управляет адаптивным раскрытием.

- /: краткое введение и ссылки на первые шаги и компоненты.
- /getting-started: установка, Minimal/Full, импорты CSS и первый пример.
- /components/<slug>: отдельная страница каждого публичного компонента,
  включая новые части Sidebar. На странице назначение, примеры, код,
  краткая таблица собственных props и замечания о доступности.
- /guides/forms: существующая составная форма и её состояния.
- /guides/theming: текущие настройки темы и примеры CSS variables.
- /guides/signals: живые примеры значений, disabled и class через signals.
- Неизвестный маршрут: страница 404 со ссылкой на начало.

Использовать существующий CodeExample с TanStack Highlight и копированием.
Перенести текущие сценарии диалогов, состояния форм и длинный контент на
соответствующие страницы, сохранить проверяемое поведение и управление фокусом.
Вся галерея должна быть на английском: навигация, документация, таблицы props,
кодовые примеры и их комментарии, демонстрационные данные, сообщения,
страница 404, document.title и доступные подписи aria-label. Русские строки
не допускаются в пользовательском интерфейсе галереи.

## Маршруты и размещение

preact-iso используется только в галерее. Применять LocationProvider,
Router/Route и ErrorBoundary. Единый реестр страниц задаёт slug, название,
группу и компонент страницы; Sidebar строится из того же реестра.
Обновлять document.title после перехода, переносить фокус на заголовок
страницы после клиентского перехода и предоставлять skip-link к main.

Галерея сейчас публикуется через GitHub Pages. Использовать base-aware URL
и prerender всех известных страниц с preact-iso и Vite preset, чтобы прямое
открытие и перезагрузка вложенных URL работали без серверного SPA fallback.
Генерировать 404.html. Проверить сборку под вложенным repository base.
В prerender нельзя обращаться к window/document при импорте модулей или
первом серверном render; браузерные настройки подключаются при hydration.

## Состояние и зависимости

@preact/signals и preact-iso — зависимости разработки галереи. Они не должны
стать runtime или обязательными peer-зависимостями библиотеки.
Контракт библиотеки остаётся JSX.Signalish, без импорта @preact/signals.

Настройки темы и CSS preset живут в одном gallery store на signals.
Начальные серверные значения детерминированы; после hydration считываются
query-параметры. Клиентские переходы сохраняют параметры оформления.
Изменение настройки обновляет URL через replaceState, переходы между
страницами создают записи истории. Back/Forward синхронизируют маршрут
и настройки. Системная тема и подключение optional CSS сохраняются.
Локальные состояния демонстраций изолированы от глобальных настроек.

## Проверка

Поведенческие тесты Sidebar проверяют native props/ref, активность,
aria-current, подписи групп, отсутствие classes в DOM, SignalLike-классы
и значения. Пакетные контракты проверяют экспорт props и запрет classes
для одноэлементных частей, неизвестных slots и неверных props.

Тесты галереи проверяют маршруты, 404, историю, сохранение настроек,
глобальный store, copy и сохранённые сценарии компонентов. Проверить
prerender и hydration с query-настройками без ошибок и предупреждений.

Запустить build, check, build:gallery и проверки одного архива с обоими
поддерживаемыми Preact peers. В браузере проверить прямой вход и reload
вложенной страницы, Back/Forward, клавиатуру, фокус после перехода,
узкий экран, обе темы и Minimal/Full. Если среда не позволяет проверить
forced-colors или реальный screen reader, явно перечислить эти ограничения.
