# Дизайн preact-fluent-ui

Дата: 2026-10-02. Статус: базовый проект дизайна для обсуждения.

Имя проекта: `preact-fluent-ui`. Имя npm-пакета: `@violice/preact-fluent-ui`.
Название выбрано пользователем. Остальные решения ниже являются предложениями; реализация и публикация в эту задачу не входят.

## Цель

Вынести повторяющиеся компоненты и оформление из `port-proxy`, `route-vpn`, `hosts-editor` и `xbox-dns` в одну библиотеку. Исправления поведения и стилей выпускаются один раз, приложения получают их при обновлении зависимости. Приложения сохраняют собственные цвета, страницы, навигацию и независимые релизы.

Библиотека предоставляет Preact-компоненты в стиле Windows 11 / Fluent. Это самостоятельный проект, а не официальный пакет Microsoft и не обёртка над нативным WinUI.

## Что изучено

Проверены локальные `package.json`, публичные экспорты `src/shared/ui`, компоненты, CSS Modules и `src/app/styles/global.css` четырёх приложений. В `rmu` проверены `AGENTS.md`, `package.json`, `tsdown.config.ts` и `.github/workflows/publish.yml`.

Совпадение части файлов не означает полной совместимости всех компонентов. При переносе сравниваются props, состояния, обработка ref, классы и клавиатурное поведение.

## Подход и границы

Рекомендуется отдельный репозиторий с одним npm-пакетом. Монорепозиторий облегчил бы синхронные изменения, но потребовал бы объединить процессы разработки приложений. Копирование исходников или git submodule сохраняют ручное управление обновлениями и менее удобны для обычного npm-потребления.

В первую версию входят:

- Button, Card, InfoBar, StatusBadge.
- Modal, ConfirmDialog, DialogHeader, DialogBody, DialogFooter.
- Select, PageHeader, EmptyState, Icon и тип IconName.
- CSS-токены и системные светлая/тёмная темы, поддержка forced colors и reduced motion.
- Локальная галерея с примерами компонентов и документацией подключения.

Tauri API, Rust, бизнес-логика, Signals-модели приложений, маршрутизатор, оболочка с сайдбаром, таблицы конкретных сущностей и TextComparison остаются в приложениях. Новые Input, Checkbox и другие элементы добавляются отдельными задачами после подтверждения потребности.

## Публичный API

Компоненты и типы импортируются из корня пакета. Внутренние пути исходников закрыты через `exports`. Props опираются на нативные Preact JSX-типы; `ref`, обработчики, `aria-*` и `data-*` должны доходить до соответствующего элемента.

Существующие variants и sizes Button сохраняются. Основное расширение API при переносе касается согласованных публичных типов, локализации и устранения различий между копиями. Для `class` и `className` задаётся единое поведение: оба поддерживаются и объединяются со внутренним классом. У Select нужно отдельно документировать класс контейнера и класс самого select.

ConfirmDialog получает текстовые props для кнопок отмены, подтверждения и выполнения. Библиотека не фиксирует русский язык. Каждый экземпляр диалога получает уникальный идентификатор заголовка; текущий постоянный `confirmation-title` не переносится как общий контракт.

Пример предлагаемого подключения:

```tsx
import { Button, Card } from '@violice/preact-fluent-ui';
import '@violice/preact-fluent-ui/theme.css';
import '@violice/preact-fluent-ui/styles.css';
import './app-theme.css';

export function Example() {
  return <Card><Button variant="primary">Сохранить</Button></Card>;
}
```

## Стили и темы

Предлагаемые CSS entry points:

- `theme.css`: CSS-переменные на `:root`, синий акцент по умолчанию, автоматическая тёмная тема через `prefers-color-scheme`.
- `styles.css`: собранные стили компонентов, включая их focus-visible, forced-colors и reduced-motion состояния.
- `reset.css`: отдельное необязательное подключение базовых глобальных правил и типографики.
- `native-controls.css`: отдельное необязательное оформление обычных input, textarea и select для постепенной миграции текущих приложений.

Импорт JavaScript не меняет глобальный CSS. Основное подключение требует явного импорта theme и styles. Глобальные правила не включают стили страниц, минимальную ширину окна, навигацию, таблицы или layout приложения. Select получает все необходимые собственные стили без зависимости от native-controls.

На первом этапе сохраняются существующие имена переменных `--color-*`, `--space-*`, `--radius-*`, `--font-*`, `--type-*` и `--shadow-*`, используемые компонентами. Это снижает объём изменений в приложениях. Переменные оболочки, например hero/mica/nav, остаются локальными. Публичный список токенов документируется.

По умолчанию `--color-primary` и его состояния ссылаются на accent; `--color-on-primary` на on-accent. Xbox DNS переопределяет их отдельно, а также нужные цвета поверхностей. Переопределения приложения подключаются после библиотечных файлов и задаются отдельно для светлой и тёмной темы. Шрифты выбираются из системных, файлы Segoe UI не распространяются.

Первая версия следует системной теме. Принудительное переключение темы и ThemeProvider не входят в начальный API. Портальные диалоги наследуют тему от `:root`; тема отдельного вложенного контейнера в первой версии не поддерживается.

## Доступность и поведение

Modal сохраняет начальный фокус, обработку Escape, замыкание Tab, блокировку фона через inert, блокировку прокрутки и возврат фокуса к инициатору или fallback. Проверяются скрытые и отключённые элементы, отсутствие доступных controls и размонтирование инициатора. Полноценный стек вложенных модалок не входит в первую версию; ограничение одного активного Modal документируется.

ConfirmDialog при busy запрещает повторное подтверждение и закрытие через отмену, Escape и backdrop. Это UI-состояние, управление операцией остаётся у вызывающего приложения. Нативные формы сохраняют семантику и клавиатурное поведение. Декоративные иконки скрыты от accessibility tree; доступное имя иконковой кнопки задаёт приложение.

Тема высокой контрастности использует системные цвета, а фокус виден без зависимости от тени. При reduced motion отключаются необязательные переходы.

## Сборка и npm-пакет

Рекомендуется Vite library mode для JavaScript и CSS Modules, плюс отдельная генерация деклараций TypeScript. В отличие от rmu, здесь важна обработка CSS. Vite уже используется во всех потребителях, поддерживает библиотечную сборку и отдельный CSS-артефакт. tsdown остаётся альтернативой, если его CSS-сборка даст столь же простой проверенный результат.

Начальный формат JavaScript: ESM с sourcemaps и `.d.ts`. CJS не нужен текущим ESM/Vite-приложениям; в отличие от rmu, двойной формат не добавляется без потребителя. Preact и все его subpaths, включая hooks, compat и jsx-runtime, остаются external. Preact задаётся peer dependency, первоначально в диапазоне `^10.27.0`; минимальная версия проверяется отдельно. CVA и clsx используются внутри сборки, без требований к приложению устанавливать их отдельно.

Экспорты пакета: корень с types/import и четыре явных CSS subpaths. В npm включаются `dist`, README, LICENSE и notices используемых сторонних материалов. Исходники приложения и галерея не публикуются. CSS отмечается в `sideEffects`, чтобы сборщик потребителя его не удалял. JavaScript допускает tree shaking; общий CSS первой версии содержит стили всех компонентов.

Иконки переносятся из существующего ограниченного набора Fluent SVG с сохранением источника и лицензионного текста. Набор имён объединяется после проверки различий; полный каталог иконок Microsoft в пакет не добавляется. Для собственного кода предлагается MIT, как у rmu; лицензии заимствованных материалов сохраняются отдельно.

## Структура проекта

```text
src/
  components/         # компоненты и соседние CSS Modules
  icons/              # SVG paths, типы и атрибуция
  styles/             # theme, reset, native-controls
  index.ts            # публичные exports
examples/
  gallery/            # локальное Preact/Vite приложение
tests/
  package-consumer/   # проверка установленного npm-архива
docs/
  superpowers/specs/
licenses/
.github/workflows/
```

FSD приложений не переносится в библиотеку: здесь нет сущностей и бизнес-фич. Node 24 используется для разработки и CI, как в rmu; это не требование к браузеру приложения. Oxlint/Oxfmt и Vitest сохраняют привычные инструменты четырёх приложений.

## Проверки и публикация

На push/PR выполняются typecheck, lint, format, поведенческие тесты, сборка и проверка npm-архива. Пакет создаётся через npm pack и устанавливается в тестовый потребитель вне каталога исходников. Проверяются публичные imports, декларации типов, CSS exports, production build и отсутствие второго Preact в сборке.

Поведенческие тесты сосредоточены на Modal, ConfirmDialog и передаче нативных props/ref. Галерея показывает варианты компонентов, длинные тексты, disabled/busy, светлую/тёмную тему и пользовательский зелёный акцент. Визуальная проверка включает узкое окно, клавиатуру, forced colors и reduced motion. Размер JS и CSS измеряется после первой рабочей сборки; лимит rmu в 2 KB не переносится на UI-библиотеку.

Публикация предлагается по опубликованному GitHub Release: повторные проверки, соответствие тега версии package.json, публикация проверенного архива в npm с public access. Способ npm-аутентификации настраивается владельцем при подключении репозитория: предпочтительно trusted publishing, а NPM_TOKEN из rmu может служить альтернативой. Provenance включается при подходящей настройке CI. Автоматическое повышение версии на каждый merge не требуется.

Первая версия предлагается `0.1.0`. Приложения обновляются явно, с lockfile. Изменения props, имён и смысла токенов отмечаются в changelog, включая несовместимые изменения до 1.0.

## Поэтапное подключение

1. Сравнить копии компонентов, собрать общий API и токены, перенести поведенческие тесты.
2. Собрать пакет и галерею, проверить npm-архив в отдельном потребителе.
3. Первым подключить port-proxy, где уже представлен почти весь начальный набор. Проверить формы, диалоги и темы в приложении.
4. Подключить hosts-editor и route-vpn, затем xbox-dns с сохранением зелёных поверхностей и отдельного primary.
5. Удалять локальные копии только после проверки заменённых экранов. Временный shared/ui barrel допустим для сохранения импортов и FSD-границ во время миграции.

Успешный результат: четыре приложения используют опубликованный пакет вместо копий его компонентов; общий фикс требует одного изменения в библиотеке; оформление и значимое поведение каждого приложения сохраняются; установленный архив работает без доступа к исходникам соседних репозиториев.

## Риски и следующий шаг

Главные риски: незаметные различия между копиями, зависимость компонентов от глобальных стилей, регрессии управления фокусом и потеря оформления Xbox DNS. Их проверяют сравнением API, тестами установленного пакета и проверкой экранов при миграции.

Этот документ фиксирует базовое предложение. После его согласования можно подготовить отдельный план реализации. Создание GitHub-репозитория, настройка npm, реализация и миграция приложений выполняются последующими задачами.
